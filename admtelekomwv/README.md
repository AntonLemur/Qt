# QML Async libvlc Video Frame Extractor & Renderer (C++20 / Qt 6)

Высокопроизводительный асинхронный движок для захвата, декодирования и рендеринга кадров видеопотоков (включая RTSP/IP-камеры и локальные файлы) на базе нативной библиотеки `libvlc`, интегрированный в графический конвейер Qt Quick (QML) без блокировки основного GUI-потока.

## 🔥 Ключевые архитектурные особенности проекта

*   **Асинхронный конвейер (Non-blocking GUI):** Реализован кастомный провайдер изображений на основе `QQuickAsyncImageProvider`. Задачи декодирования кадров инкапсулированы в `QRunnable` и выполняются параллельно в глобальном пуле потоков `QThreadPool`, что гарантирует стабильные 60 FPS интерфейса при прокрутке списков медиа-ресурсов.
*   **Низкоуровневый Interop (C / C++):** Захват кадров реализован через прямую регистрацию статических Си-колбэков видеовывода (`libvlc_video_set_callbacks`) в ядро медиаплеера VLC. 
*   **Zero-Copy в памяти:** Декодер VLC пишет сырые пиксели кадра в формате `"RV32"` (RGBA) напрямую в выделенный `std::vector<uchar>` внутри контекста памяти приложения. Исключены лишние аллокации и копирования данных.
*   **Потокобезопасная синхронизация (Lock-free элементы):** Синхронизация состояний перемотки (Seek) и готовности кадра между внутренними потоками VLC и пулом Qt реализована на базе атомарных флагов `std::atomic<bool>`, что исключает взаимные блокировки (Deadlocks).
*   **Кастомные URL-схемы в QML:** Связывание C++ ядра с декларативным слоем интерфейса реализовано через протокол `image://async_provider/`, позволяя запрашивать миниатюры динамически.

## 🛠 Технологический стек

*   **Язык:** C++20 / STL
*   **Фреймворк:** Qt 6 (Qt Quick, QML)
*   **Медиа-ядро:** Нативное API `libvlc` (VideoLAN)
*   **Сборщик:** CMake
*   **Платформы:** Кроссплатформенная архитектура (Windows, Linux, Android)

## 📁 Краткое описание ключевых компонентов

*   `vlcmanager.h` / `vlcplayer.h/.cpp` — Обертка над нативным API libvlc, инициализация ядра плера, управление состояниями воспроизведения, позиционированием и регистрация системных колбэков.
*   `imageresponse.h/.cpp` — Асинхронная задача `QQuickImageResponse` / `QRunnable`, реализующая логику ожидания конкретного кадра, его конвертацию в `QImage` и генерацию текстуры графического процессора (`QQuickTextureFactory`).
*   `asyncImageprovider.h` — Точка входа для QML-движка, перехватывающая запросы по схеме `image://` и распределяющая их по потокам пула.
*   `Main.qml` — Декларативный интерфейс, демонстрирующий плавную отрисовку и использование асинхронного провайдера.

## 🚀 Использование в QML

Запрос превью кадра из видеофайла или RTSP-потока осуществляется одной строкой:

```qml
Image {
    source: "image://async_provider/" + videoFilePath
    asynchronous: true
    cache: true

    // Плейсхолдер на время асинхронного декодирования кадра в C++
    Rectangle {
        anchors.fill: parent
        color: "#1e1e1e"
        visible: parent.status != Image.Ready
    }
}
```
